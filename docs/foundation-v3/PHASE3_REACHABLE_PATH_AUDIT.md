## Accepted test path

The Phase 3 acceptance path is intentionally narrow:

1. direct boot into the Vela test area;
2. player movement and collision;
3. Mira interaction and persistent flag;
4. encounter trigger;
5. wild Luzik battle;
6. use of `Impuls Warstwowy`;
7. battle resolution or capture with `Kula Splotu`;
8. return to overworld;
9. native save;
10. hard restart and restore.

Full menus, Pokédex/encyclopedia, world map, upstream story, link features, contests and the broader Hoenn world are outside the accepted Phase 3 path and are not approved as SOMADEX content.

## Production identity guard

The canonical Phase 3 registry and validator reject these former PoC shortcuts as production identities:

- `SPECIES_TREECKO`;
- `MOVE_POUND`;
- `ITEM_POKE_BALL`.

The Phase 3 transformer restores the upstream records modified by the Micro-PoC, creates dedicated SOMADEX IDs, then migrates only PoC-added references to those IDs.

`BALL_POKE` is deliberately not classified as an identity. In the current slice it is an internal capture-algorithm selector referenced by the dedicated `ITEM_KULA_SPLOTU` record. Its player-facing thrown-device presentation remains an explicit replacement task.

## Phase 3 acceptance consequence

Even if automated build/runtime gates pass, this audit does **not** permit a full PASS while the reachable slice still contains tracked upstream-visible UI/audio/tiles or while physical Android QA remains unperformed.

Therefore the highest result available to this implementation without those conditions being closed is **CONDITIONAL PASS**.

Full migration and bulk production remain forbidden until the Phase 3 report explicitly changes that state.
